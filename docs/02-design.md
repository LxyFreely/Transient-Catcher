# 02 · 检测器设计

> 本文档给出方案。**改动核心结构之前，请先读第 3 节的"被否决的方案"——
> 那不是随手写的，是踩过的坑。**

---

## 1. 设计目标

先把"更好"定义成可验证的东西，否则无法判断方案是否成立。

| 编号 | 目标 | 可验证形式 |
|---|---|---|
| **G1** | 密集音型不漏 | 在 BPM 160 的 32 分音型（间隔 46.9 ms）上，能输出**独立**事件，而不是被合并 |
| **G2** | 弱人声可见 | 连奏换音能被检出，且**不是**靠能量突变 |
| **G3** | 不因颤音爆炸 | 6 Hz、峰峰值 1 半音的颤音上，误报率低于阈值（见 [03-validation.md](03-validation.md)） |
| **G4** | 可解释、可调 | 每个事件都能追溯到通道与原因（瞬态 / 出生 / 迁移 / 再击） |
| **G5** | 能落地 | 全离线跑完一首 3–5 分钟的歌，耗时在可接受范围内；算法可读、可移植 |

**G1 和 G3 是一对矛盾**，整个设计的张力就在这两条之间。第 2 节会说明为什么。

---

## 2. 核心论证：为什么不能靠"细化频率"来救

这是本项目最容易走错的一步，所以单独成节。

### 2.1 颤音是什么

| 属性 | 典型值 |
|---|---|
| 速率 | 4 – 8 Hz（美声/弦乐约 6 Hz） |
| 深度 | 峰峰值 0.5 – 1 个半音（流行唱法可能只有 ±15–30 音分） |

它是 f0 的**准周期摆动**。

### 2.2 逐 bin 求导会把它变成一堆音符

若对每个频点做时域正差分，能量**每跨过一次 bin 边界**，就会在刚进入的 bin 里
产生一次正向跳变。一个颤音周期里音高上下各扫一遍，摆动范围内的每条 bin 边界
都会贡献一次。所以：

> **每秒误报 ≈ 速率 × (摆动峰峰值 / bin 宽度) × 2**

| bin 宽度 | 每秒误报（速率 6 Hz，峰峰 1 半音） |
|---|---|
| **1/4 半音（50 音分）** | **≈ 24 次/秒 → 每 42 ms 一个"音符"** |
| 半音 | ≈ 12 次/秒 |
| 全音 | ≈ 6 次/秒 |
| 现有 24 频带（≈3.75 半音/带） | ≈ 3 次/秒，且多数被 55 ms 合并吃掉 |

**结论：bin 越细，颤音误报越多，而且大致成正比。**
从 24 带做到 367 个 1/4 半音 bin，密度约 7.5 倍，误报也放大 7.5 倍。

### 2.3 而且细到这个程度也没有物理依据

1/4 半音是**恒定 Q** 的表示，Q ≈ 69。要真正做到这个分辨率，需要的窗长是：

| 频率 | 1/4 半音对应的带宽 | 所需窗长 |
|---|---|---|
| 55 Hz | ≈ 0.8 Hz | ≈ 1.2 秒 |
| 1 kHz | ≈ 14.5 Hz | ≈ 69 ms |
| 10 kHz | ≈ 145 Hz | ≈ 7 ms |

而这套系统用的是**固定 23 ms 窗**，其频率分辨率约 43 Hz：

| 频率 | 一个 23 ms FFT bin 相当于 | 1/4 半音是 |
|---|---|---|
| 200 Hz | ≈ 340 音分 | 50 音分 |
| 1 kHz | ≈ 73 音分 | 50 音分 |
| 5 kHz | ≈ 15 音分 | 50 音分 |

也就是说，**在约 1.5 kHz 以下，1/4 半音比 23 ms 窗所能分辨的还细**，
那部分 bin 是用插值造出来的，不含信息。

### 2.4 由此得到的设计律

> **频率分辨率是"错误预算"，不是"性能指标"。**
>
> 提高它，会同时提高对颤音、抖动、混响的敏感度。
> 只有在你能用别的手段压住这些误报时，才允许提高它。

这正是为什么方案里频率轴的处理是**分裂的**：

- 抓**瞬态**的通道：频率**粗**（天然抗颤音），只把时间轴做细。
- 抓**音高**的通道：频率**细**，但颤音靠**轨迹的持续性判据**压住，而不是靠 bin 宽。

## 3. 被否决的方案（决策记录）

| 编号 | 方案 | 否决理由 |
|---|---|---|
| **D1** | 把频带细化到 1/4 半音后再逐 bin 求导 | 见第 2 节：误报正比于 bin 密度；且低于窗的物理分辨率。**这条路会把 32 分的问题换成颤音的问题。** |
| **D2** | 用完整重分配（时间 + 频率都搬） | 时间重分配会**破坏均匀时间栅格**，之后无法再逐帧求差或逐帧跟踪。若要用时间重分配的锐化效果，检测方式必须改成竖直能量检测，那是另一套系统。**只做频率重分配（同步压缩）**，且只用在通道 B——见 D6。 |
| **D3** | 纯逐 bin 时域导数作为唯一 ODF | 三重问题：① 颤音（第 2 节）；② 一个音变会点亮两个 bin（能量流入新 bin、流出旧 bin），造成重复计数；③ 无法区分"起音"与"衰减/释放"。 |
| **D4** | 只跟踪一条 f0 轨迹 | 基频弱或缺失时（人声、低音区）直接失效。**改为跟踪全部谐波分音**，用冗余换鲁棒性。 |
| **D5** | 直接用神经网络 ODF / 转录模型 | **暂缓，不否决。** 这是当前 SOTA（见 [04-references.md](04-references.md)），但会引入模型体积、依赖和不可解释性，不适合作为"轻量参考实现"的第一版。定位为**后期对照基线**。 |
| **D6** | 在通量通道里使用频率重分配 | **P0 实测否决。** 重分配把一条分音的能量压进单个 bin，重分配估计的逐帧抖动因此变成"整条脊线在 bin 间跳"，产生大量假通量。实测：稳定长音的 p90 从不重分配的 **0.083** 升到重分配的 **5.17**（差 62 倍），且加宽 max-filter 也压不下去。**重分配只留给通道 B**，那里的抖动由轨迹连续性吸收。详见 [05-p0-results.md](05-p0-results.md) F3。 |
| **D7** | 自适应阈值只用相对分位数 | **P0 实测要求补强。** 纯相对阈值没有绝对噪声底：当信号里只有低电平波动时，它会把波动本身归一化放大成"信号"。实测基线在**完全平稳的长音**上给出 4.2 次/秒的事件。这也解释了为什么 max-filter 把原始通量压了 100 倍，事件数却几乎不变。**必须在相对阈值之上再叠加一道绝对噪声底。** 详见 [05-p0-results.md](05-p0-results.md) F4。 |

## 4. 架构总览

~~~text
音频（单声道 PCM）
  │
  ├─ 通道 A · 瞬态通道 ─────────────────────────────┐
  │    短窗 → 粗对数频带 → 沿频率 max-filter        │
  │    → 正半波通量 → 自适应阈值                    │
  │    产出：瞬态 ODF 曲线                          │
  │                                                 │
  └─ 通道 B · 谱峰追踪通道 ────────────────────────┤
       STFT（长窗）→ 频率重分配 → 团块分割           │
       → 轨迹关联（预测-新息）→ 事件（出生/迁移/     │
         消亡/再击）→ 谐波分组 → 音符级置信度        │
       产出：谱峰 ODF 曲线 + 音符事件               │
                                                    │
                        ↓                           │
                 事件层融合（NMS + 自适应阈值）  ←──┘
                        ↓
              统一输出：onsets[] / notes[] / curves{}
~~~

**为什么不能合并成一张图：** 抗颤音要求频率**粗而稳**，抓瞬态要求时间**细**——
这是时频不确定性的直接后果，不是实现问题。所以必须在**表示层**分离，
只在**事件层**汇合。

## 5. 通道 A · 瞬态通道

**职责**：抓鼓点、钢琴起音、辅音、以及其他一切**宽带瞬态**。

### 5.1 处理

1. **短窗**（实测取 16 ms 最好，见 [05-p0-results.md](05-p0-results.md) F8）
   - 真实的 32 分琶音（46.875 ms）用 46 ms 的窗会被抹平：安静段通量 98 → 691（win=16）。
   - 高频段可以更短；是否做真正的多分辨率待定。

2. **对数频带聚合，但不要过细**
   - 频带宽度保持 **≥ 1 个半音**（现有系统是 3.75 半音，可以细一些，但**不要**到 1/4 半音）。
   - 1/4 半音栅格（362 格）也可以，只要配合下面的 max-filter。

3. **沿频率做 max-filter（抗颤音的关键）**
   - **只对前一帧**沿频率做最大值滤波，再与当前帧逐 bin 相减：
     d[n][b] = max(0, spec[n][b] − max over |k−b| ≤ h of spec[n−1][k])
   - **两帧都滤波是错的**：移动中的脊线会在"膨胀边界"上产生假通量（P0 实测踩到过）。
   - 这是 [SuperFlux](https://research.jku.at/en/publications/maximum-filter-vibrato-suppression-for-onset-detection/)
     的机制。P0 实测（[05-p0-results.md](05-p0-results.md) F2）：配合"不重分配"，
     宽度 17（≈4.25 半音）可把稳定长音的原始通量 p90 从 8.14 压到 **0.083**，
     而颤音仍保留 14.82 —— 分离度约 **178 倍**。
   - 宽度是**取舍参数**，而且**不要开太宽**：F8 实测 17 格（4.25 半音）会把
     32 分琶音的音程当成"能量本来就在那儿"而抑制掉（安静段通量 98 vs 1 格时的 432）。
     **通道 A 取 5 格（≈1.25 半音）**；宽度 65 那类只适合当诊断手段，不适合当默认值。

4. **本通道不做频率重分配。**（决策 D6）
   重分配把能量压进单个 bin，会带来逐帧抖动。实测稳定长音的 p90 反而从 0.083 升到 5.17。

5. **能量归一化通量 + 全局分位数归一化**（F8 修正了 D7 的表述）
   - 通量尺度用 **flux / 局部能量**，而不是绝对通量。
     起音强度应当是"相对当前能量变化了多少" —— 这样响亮段与安静段才可比。
     原方案只在这里失守：真实素材的安静段通量 98 对活跃段 982。
   - 归一化用**全曲**分位数（0.99），**不要做局部归一化，也不要减局部均值**。
   - 原因见 F8.3：能量归一化后的比值，在真实音乐（中位 1.4e-1）
     和稳定长音的数值涟漪（1.2e-2）之间**差一个数量级**；
     局部归一化是尺度无关的，会把这个区别抹掉，于是把噪声也放大成信号
     （实测炸出 38 个事件）。
   - 因此 **D7 的"另加一道绝对噪声底"不再需要单独设计** ——
     把能量归一化做在前面，噪声底自然就分开了。

6. **相对峰阈值：峰值须达到局部最大峰的 rel_gamma 倍**（F9）
   - 动因：真实歌曲里一个延音被检成 6 个音头，根因是**高次分音的拍频**。
   - 绝对下限分不开（A 段与 B 段的通量中位数几乎相同），
     但"相对 ±600 ms 内的最大峰"可以：6 → 1，且 S1/S0 不退化。
   - 代价：B 段召回 3 → 2。**取舍是本质的**。
     进一步区分需要通道 B 的音高轨迹（拍频不改基频，换音会改）。

7. **输出层的非极大抑制要放开（G1 的解药）**
   - 现有系统在这里用 55 ms 硬间距 + ±30 ms 局部极大窗。
   - 本通道改为：**局部极大窗口 = 2 帧（20 ms）**，最小间距降到 **15–20 ms**，
     并且把它作为可调参数暴露出去。
   - 关键判断依据是"**是不是真的有两个能量峰**"，而不是"距离够不够远"。
     真正的密集音型在两个峰之间会有能量谷；重复检测不会。

### 5.2 为什么这样就能救 32 分

46.9 ms 的间隔，对 10 ms 帧移来说是 4–5 帧。只要不再人为合并，
它**本来就能被分辨**。通道 A 的核心改动其实就是"**把输出层的闸门打开**"。

## 6. 通道 B · 谱峰追踪通道

**职责**：抓**音高变化**——钢琴的音高走动、人声的转音与换音。
这是**现有系统完全没有观测的那条轴**。

### 6.1 为什么是"追踪"而不是"求导"

关键差别在于追踪引入了**稳态与持续性**：

| 情形 | 逐 bin 导数 | 轨迹追踪 |
|---|---|---|
| 颤音（小幅往返） | 每次跨 bin 都跳一次 | 只是小幅往返，没有"搬迁" |
| 音符变化（台阶） | 有峰 | 峰**稳定迁到**新位置 |
| 弱人声（基频弱） | 看不见 | 谐波冗余，基频丢了也能跟 |
| 副产品 | 只有 onset | **顺手得到音高** |

### 6.2 处理

**第 1 步 · 频率重分配（同步压缩）**

- 用较长窗（46–93 ms 量级）做 STFT，以求频率精度。
- 需要原窗 + 时间导数窗 + 频率导数窗三次变换（或等价实现）。
- **只重分配频率，保留帧栅格**（对应 D2 的决策）。
- 效果：能量脊线被锐化，f0 估计更干净。

**第 2 步 · 团块分割**

- 把重分配后的能量按**连通域 / 分水岭**切成团块（blob）。
- 每个团块自带：**质心（音分）**、**总能量**、**频率跨度**。
- 这个"跨度"就是天然的"影响范围"，**不需要再做高斯模糊**
  （模糊会抵消重分配的锐化效果）。
- 跨度必须用**音分**而非 Hz，最好自适应到局部谐波间距的一半（≈ f0/2）。

**第 3 步 · 轨迹关联（预测-新息）**

对每条轨迹维护一个预测器（常速 / α-β / Kalman）：

~~~text
pred_cents = cents_prev + velocity_prev * dt
innovation = cents_now - pred_cents            # 单位：音分

关联代价 = |innovation| / gate_cents + |Δlog(energy)| / gate_energy
~~~

- 匹配窗口按**音分**设置，不按 Hz。
- 未匹配的团块 → 新轨迹（**出生**）。
- 连续未匹配超过 maxAge 帧的轨迹 → **消亡**。

**第 4 步 · 事件定义**

| 事件 | 定义 | 语义 |
|---|---|---|
| **birth** | 新轨迹，且能量 > 阈值，且存活 ≥ minFrames | 新声音成分出现 |
| **move** | 新息超过阈值，**且新位置保持 ≥ holdFrames** | 音高发生变化 |
| **death** | 轨迹消亡 | 声音结束 → **offset**，不是 onset |
| **rebirth** | 消亡后，在 rebootMs 内、centsTol 范围内又出现 | **同音再击** → onset |
| **split / merge** | 团块分裂 / 合并（可选） | 和音、齐奏 |

> **move 的持续性判据是整个方案的分水岭。**
> 因为颤音 ±0.5 半音和真实的半音级音高变化**在位移量上是同一量级**，
> 单靠位移阈值分不开。能分开它们的只有"**是否稳定停在新位置**"：
> 音符变化是搬迁，颤音是来回。没有这一条，重分配的逐帧抖动会让 move 每帧都触发。

> **death 归入 offset 而不是 onset。**
> 唯一的例外是 death 后紧跟同频率的 birth——那才是同音反复。

**第 5 步 · 谐波分组**

一个钢琴音会同时让 8–10 条分音出生或迁移。若每条分音的置信度独立累加，
**一个音会变成一堆假峰**。所以：

- 把**同帧、频率成整数比**（f_i ≈ k·f0）的事件归为一个**音符事件**；
- f0 由该组联合估计（不用单条分音）；
- 这一步还顺带区分了"音"与"鼓"：
  - 谐波性出生 → 音符
  - 非谐波性宽带出生 → 打击乐

**第 6 步 · 置信度聚合**

~~~text
note_confidence = Σ_{group} energy_weight
                  （建议用 √energy 或对数聚合，避免被单个响音主导）
~~~

### 6.3 通道 B 的已知困难

| 困难 | 说明 | 缓解 |
|---|---|---|
| **轨道交换** | 多声部时谐波穿叉，关联错了就凭空造出一次"大幅移动" | 用预测-新息而不是最近邻；对高能量轨迹更保守 |
| **重分配抖动** | 即使稳定长音，逐帧质心也有小幅抖动 | move 必须有持续性判据 + 位移阈值按音分标定 |
| **瞬态期的伪峰** | 起音瞬间是宽带的，会产生一堆短命团块 | 用 minFrames 门限滤掉短命轨迹 |
| **同音连奏** | 无间隙的同音重复，信号里没有信息 | **物理上不可分**，见第 8 节 |

## 7. 融合与后处理

1. **各自归一化**：两条曲线用同一套自适应阈值（局部均值 + 分位数）归一化到可比尺度。
2. **事件层合并**：同一个时刻附近（**±15–30 ms**）的候选**归并**
   - 为一个事件（用于 onset 输出），
   - 但**保留 kind 标签**（transient / birth / move / rebirth）——这是 G4 的要求。
3. **最终 NMS**：在合并后的置信度上做非极大抑制，窗口取 2×帧移（20 ms）。
4. **输出**。

### 7.1 为什么必须在事件层融合

因为两条通道的**失效模式不相关**：

- 通道 A 对鼓和瞬态强，对连奏人声弱；
- 通道 B 对人声和音高变化强，对纯打击乐弱（鼓没有稳定分音，只会产生短命团块，
  正好被 minFrames 滤掉）。

不相关的失效模式，正是融合能提升整体表现的依据。

## 8. 已知局限（诚实清单）

这些**写进文档、不藏着**，也不要指望实现时能绕开：

1. **无间隙的同音连奏，物理上不可分。**
   如果两个相同音高的音符之间没有能量凹陷、没有相位突变，
   音频里就不存在"这里有两个音符"的信息。任何算法都只能靠节奏先验猜。
   **这是信息论限制，不是算法不够好。**

2. **纯打击乐素材，通道 B 基本不出力。**
   鼓是宽带、无稳定分音的，峰追踪只看到一群短命团块。
   这类素材完全依赖通道 A。所以通道 B 不是通道 A 的替代品。

3. **参数比单 ODF 多一个数量级。**
   门限、持续性窗长、出生/消亡阈值、谐波分组容差……
   每一项都要标定，坏起来不容易定位。

4. **计算成本高。**
   重分配需要约 3 次变换；轨迹关联是组合问题。
   相对现有单分辨率 FFT，粗估 20–100 倍 CPU。
   **好在整条链路是离线的且带缓存**，一首 3–5 分钟的歌在几十秒内完成是可接受的，
   但**不能用于实时**。

5. **多分辨率会带来边界问题。**
   不同频带用不同窗长，拼接处会有时间对齐与能量标定的麻烦。

## 10. 技术栈与仓库结构

### 10.1 为什么选 Python

| 理由 | 说明 |
|---|---|
| **性能不是瓶颈** | 分析是全离线的。numpy / scipy 的 FFT 是**预编译的 C / Fortran**（pocketfft、OpenBLAS），我们只是调用它；真正自己写的热点只有"轨迹关联"这类循环，而 **numba** 可以把它 JIT 掉。一首 3–5 分钟的歌在几十秒内完成是可接受的。 |
| **重分配频谱的显示** | GUI 的核心是重分配频谱 + 音头标签 + 可缩放时域。这需要**按可见时间窗按需渲染**，Python + Qt 比在浏览器里手写画布更直接。 |
| **依赖已经就位** | conda 里 numpy / scipy / matplotlib / numba / PySide6 都是现成的。**不依赖 librosa**——STFT、频率重分配、对数重 bin 全部自己实现，算法在仓库里完全可见。 |
| **可移植性** | RhyDive 侧是 Electron + Web Audio，所以本仓库**不以"可直接 drop-in"为目标**，而以**算法可读、可复现、可移植**为目标。移植到 JS 的工作量主要在 FFT 与 STFT 层，是机械翻译。 |

> **关于"Python 会不会因为不能预编译而极慢"：不会。**
> 需要"预编译"的从来不是你的代码，而是被调用的数值内核——numpy / scipy 已经是
> 编译好的机器码。Python 的慢只会出现在你自己写的逐元素循环里，
> 而那部分恰好只有轨迹关联一处，可以用 numba 或向量化解决。
> 反过来说，如果改用 JS 自己写 radix-2 FFT，DSP 内核**反而会比 numpy 慢**。

### 10.2 计划结构

~~~text
src/transient_catcher/
  signals.py        # 合成测试信号（P0）
  dsp.py            # STFT / 频率重分配 / 对数重 bin / max-filter
  odf.py            # 三种 ODF + 峰值挑选
  transient.py      # 通道 A（P1）
  peaks.py          # 团块分割（P2）
  track.py          # 轨迹关联（P2）
  group.py          # 谐波分组（P2）
  fuse.py           # 融合与 NMS（P3）
  detect.py         # 对外接口
scripts/
  p0_synthetic.py   # P0：合成信号三曲线对照
  detect.py         # 命令行壳
gui/
  main.py           # PySide6 测试 GUI（P4）
out/                # 跑出来的图与指标（不入库）
~~~

> 标了 P1 / P2 / P3 的文件是**分批加**的，不要一次全建空壳。

### 10.3 CLI 的取舍

命令行壳**只原生支持 WAV**（用 soundfile 读写）；其它格式在检测到系统有 ffmpeg 时转码。
理由：避免在分析核心引入解码依赖。GUI 侧的解码能力是另一回事，见第 4 节。
