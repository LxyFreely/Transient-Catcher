# 07 · 提案：用「频带复核 + 多数投票」压低误检

> **这份文档可以直接当 GitHub issue 的正文用。**

> 它是一份**独立实现**的参考方案，不含 RhyDive 的任何代码或资源；
> 所有涉及现有检测器的地方都是**行为描述与独立复述**，不是引用实现。
> 采不采用、采用多少，完全由你决定。

## 0. 一句话

现在这条链路在**混合编曲**上误报偏多（实测精确率 36–39%）。

**不需要改你现在的检测器。** 只要在它的输出后面加一层
「**同一条检测跑三遍不同频带，多数同意才保留**」，
就能把**误报减少 78%**，代价是真阳性减少 15–40%。
这一层是纯 numpy，约 60 行，不引入任何模型，可以离线跑。

如果只做一件事，就做这一件。

---

## 1. 我们观察到的现象

在带人工谱面的素材上（谱面是**下界**，所以真实精确率高于此，但仍偏低）：

| 素材 | 召回 | 精确 |
|---|---|---|
| HyuN - Infinity Heaven（Ad Infinitum，710 个音符） | 93% | 36% |

在**真值精确**的自建测试集上（音频由 MIDI 渲染，每个发声的音符都在真值里），
误报占检出的比例：

| 素材 | 检出 | 命中 | 误报 | 占比 |
|---|---|---|---|---|
| 纯钢琴（Antikythera） | 2038 | 1237 | 801 | **39%** |
| 完整编曲（18 轨，含鼓） | 3425 | 1159 | 2266 | **66%** |

### 1.1 误报长什么样（这一节是关键）

我们把误报逐条拆开看过：

- **强度和真音头完全一样**（中位都是 0.57，命中与误报不可分）
- **82% 落在某个真音头之后 100 ms 以内**
- 只有 **5%** 落在静音里

也就是说：**误报不是随机噪声，是音符自身的衰减、双弦拍频、踏板共鸣**
产生的谱变化 —— 它们在「帧间谱变化」这个量上和真起音长得一模一样。

**结论：任何幅度阈值都分不开它们。** 我们实测过下限、相对峰阈值、
输出层最小间距三种旋钮，全都是**按比例同时砍掉真阳性和误报**，精确率几乎不动。

## 2. 提议

### 2.1 做法

把同一条检测函数用**三个频带**各跑一遍（**只改带通范围，其它参数一字不动**）：

~~~
低  65 - 600 Hz
中  600 - 2500 Hz
高  2500 - 10000 Hz
~~~

对每个候选时刻，看**20 ms 内是否有至少两条链路也检出**；不满足就丢弃。
最后再和原结果取交集。

~~~python
def refine(base_onsets, x, sr):
    bands = [(65, 600), (600, 2500), (2500, 10000)]
    per_band = [detect(x, sr, band=b) for b in bands]
    voted = [t for t in flatten(per_band)
             if count_within(per_band, t, 0.020) >= 2]
    voted = cluster(voted, 0.020)
    return [t for t in base_onsets if has_neighbor(voted, t, 0.020)]
~~~

### 2.2 为什么有效

三条频带**各自缺的东西不一样**：

- **低频带**能看到低音区的起音，但也吃进大量的**谐波泄漏**
  （短窗下相邻谐波的旁瓣互相重叠，稳态音也会逐帧起伏）
- **高频带**对起音的对比度最大（精确率最高），但**召回很低**
- **中频带**两头不沾 —— 实测它**单独一个就比全带好**（见 2.3）

所以「只有一条带看见」的峰大概率是伪影，而真起音三条带都会看见。
这和「用两个不同的统计量取交集」是同一个机制，只是换成了频带这个维度。

### 2.3 单频带的表现

只改频带范围，其余参数一字不动：

| 频带 | 纯钢琴 召回/精确 | 完整编曲 | 真实歌曲（谱面） |
|---|---|---|---|
| 低 65–600 | 61% / 55% | 74% / 35% | 84% / 37% |
| **中 600–2500** | 56% / 86% | 76% / 49% | 92% / 52% |
| 高 2500–10k | 35% / 92% | 63% / 74% | 74% / 64% |
| 全带（现状做法） | 67% / 62% | 78% / 36% | 91% / 39% |


**中频带单独一个就全面优于全带**，精确率高 11–23 个点，召回基本不降。
这条本身可能就值得一试 —— 如果只想改一行，就把检测的频带上限收到 2500 Hz 试试。

## 3. 实测数字

| 方案 | 纯钢琴 召回/精确 | 完整编曲 | 真实歌曲（谱面） |
|---|---|---|---|
| 现有做法（对照） | 72% / 63% | 88% / 39% | 98% / 38% |
| 三带 2/3，不与原结果取交集 | 49% / 85% | 72% / 57% | 86% / 54% |
| **三带 2/3 ∩ 原结果** | 40% / 86% | 67% / 71% | 78% / 62% |


换成**误报的绝对数量**看得更清楚：

| 素材 | 现有做法 | 三带 2/3 ∩ 原结果 | 变化 |
|---|---|---|---|
| 纯钢琴 | 758 个误报 | **117 个** | **−85%** |
| 完整编曲 | 2014 个误报 | **399 个** | **−80%** |
| 真实歌曲 | 1115 个误报 | **346 个** | **−69%** |

F1 在**真实音乐**上从 0.54–0.55 提到 **0.69–0.69**；
纯钢琴素材上现有做法仍然更强（0.67 vs 0.54）。

### 3.1 权威率不要调高

要求 **3/3 全一致**会把召回砍到 20–50%，平均 F1 **反而更低**（0.49 vs 0.64）。
原因和第 1.1 节一样：误报与真阳性本来就同分布，再严的判据也只会等比例砍掉两边。
**2/3 是甜点。**

### 3.2 分带点不敏感

600 / 2500 Hz 与 1000 / 4000 Hz 的结果几乎相同
（完整编曲 0.66 vs 0.66、真实歌曲 0.68 vs 0.69）。
**不用花时间调它。**

## 4. 次要提议：密集段落放宽输出层的最小间距

如果你关心的是**漏检**（尤其是高难谱面里的密集音型），那瓶颈在输出层：

现有做法有一个**最小间距**约束（同一条输出链路上两个音头至少要隔约 55 ms）。
我们在一张含大量密集间隔的谱面上量过（World Ender，四个难度）：

| 密集段（间隔 < 55 ms）的召回 | 现有做法 | 短窗通道 |
|---|---|---|
| 1388 音符难度 | 68% | **72%** |
| 1386 | 71% | **75%** |
| 1273 | 72% | **73%** |
| 1053 | 70% | **76%** |

**放宽这个间距能拿回 4–9 个点**，而且那些多出来的检出在密集邻域里精确率不降反升
（72% / 74% vs 68% / 73%）—— 说明它们不是乱报，是原本被合并掉的真实音头。

但**不要全局放宽**：那会让普通段落多出大量误报。
建议按**局部音符密度**门控 —— 只在密度高的地方放宽。

另外我们量过一个容易踩的点：光把分析窗缩短**没有用**。
窗长从 256 点扫到 2048 点，密集段召回卡在 45–48% 一动不动；
真正的瓶颈是输出层的最小峰间距。所以别在窗长上花时间。

## 5. 我们试过，但**不推荐**的

**（a）不要整体换成我们的通道。** 我们实现了一条独立的短窗通道，
在真实编曲上它**打不过现有做法**：

| 真实编曲（18 轨） | 召回 | 精确 |
|---|---|---|
| 现有做法 | **88%** | 39% |
| 我们的通道 | 79% | 34% |

这条我们用**两种渲染方式**交叉验证过（自建合成音色、以及用
FL Studio + Sound Canvas VA 导出的真实音源），结论一致。
所以这个提案里**没有任何一处建议你替换现有检测器**。

**（b）不要在频带/阈值/窗长/帧移上继续调参。** 我们扫过这些维度，
它们只是让结果沿同一条召回–精确取舍曲线滑动，推不动前沿。

**（c）不要指望解决间隔 40 ms 以内的密集音型。** 见第 6 节。

---

## 6. 诚实的局限

1. **间隔小于 40 ms 的密集音型目前无解。** 21 ms 的分析窗意味着单个钢琴起音的
   谱变化隆起本身就有 20–30 ms 宽，它无法区分「一个长瞬态」与「两个相隔 20 ms 的瞬态」。
   缩短窗会让频谱糊掉，两个效果互相抵消。这类素材的召回两边都只有 46–56%。
2. **表现力人声（带滑音）**：精确率停在个位数，所有单分辨率参数都救不了。
   颤音是可治的，**滑音不是**（它是真实的、连续的谱变化）。
3. **有一部分「误报」是定义问题，不是算法问题。** 同一个音的衰减涟漪
   算不算一个音头，本身就依赖定义 —— 我们自己手标时也会出现过标。
   所以第 3 节的精确率请连同真值来源一起读。
4. **所有数字都依赖真值来源**：MIDI 渲染的测试集精确率是真实值；
   谱面是人工挑过的可玩音符，那里的精确率是**下界**。

## 7. 依赖与性能

- **纯 numpy / scipy**，没有任何机器学习模型，没有 librosa，没有二进制依赖
- **完全离线**，不联网、不上传音频
- 计算量约为原来的 3 倍（跑三遍）。实测 200 s 素材上概览构建 **0.8–1.3 s**
- MIT 许可

---

## 8. 为什么值得单独加这一层

它**不碰你现有的任何东西** —— 输入是现有检测器的输出，输出是过滤后的事件表，
接口只有「时刻 + 强度」两列。合不来可以直接丢掉，没有迁移成本。

而且它把「误报」这个用户最直观能感觉到的问题（一个音被敲两次）
压掉了 2/3 以上，代价是漏掉大约 1/5 的真阳性。

## 9. 怎么复现

本仓库里全部可跑：

~~~bash
python tests/test_dsp.py                 # 4 项自检
python scripts/p0_synthetic.py           # 合成信号（定结构）
python scripts/real_infinity.py          # 真实素材
python scripts/eval_chart.py             # osu 谱面评估（需要 RhyDive 本地曲库）
python scripts/eval_dense.py             # 密集段专项（World Ender）

# 真值精确的 MIDI 渲染测试集（零外部素材，从零可复现）
python scripts/midi_demo.py --outdir testdata
python scripts/midi_render.py testdata/demo_piano_dense.mid --out testdata/p.wav --voice piano
python scripts/midi_eval.py --dir testdata

# GUI：可以直接听出差别（音头提示音）
python gui/main.py --audio testdata/antikythera.wav --shot out/a.png --t0 146.5 --t1 151.5 --variant 带2/3∩A
~~~
